🩸 Blood Bank FYP — ML Forecasting Comparison OLS Linear Regression vs Random Forest | 23 months simulation data
📌 Purpose of This Comparison

The Blood Bank Management System uses OLS Linear Regression as its demand forecasting model. This standalone analysis evaluates whether a more complex model — Random Forest — would produce meaningfully better results on the same dataset, justifying the added complexity and dependency.

🔬 Algorithms Used
OLS Linear Regression (Production)
slope = (n·Σxy − Σx·Σy) / (n·Σx² − (Σx)²)
intercept = (Σy − slope·Σx) / n
predicted = max(0, slope × month + intercept)
Implemented from scratch using pure NumPy — no scikit-learn dependency. Single predictor: month index (time trend only). Fully auditable — output is one equation any clinician can read.
Random Forest (Comparison Only)
n_estimators = 100
max_depth = 5
features: month_idx, month_of_year, rolling_3, rolling_6
scikit-learn 1.9.0. Uses 4 features: time index, seasonality, 3-month rolling average, 6-month rolling average. Used here for research comparison only — not in the production system.
Feature asymmetry is intentional: OLS uses 1 feature (month index) to produce a single interpretable equation. RF uses 4 features and still only wins by ~0.11 units/month on average. Giving OLS the same 4 features would make it multivariate regression — a different model that loses the single-equation auditability that justifies its use in a clinical setting.

Note on negative R² values: R² is statistically unreliable with fewer than 10 test data points. After an 80/20 split on 23 months of data, each blood group has only 4–5 test points. Negative R² in this context does not indicate a broken model — it is a known mathematical limitation of applying R² to very small samples. MAE is the reliable metric for this comparison.

✅ Why OLS Was Chosen for the Production System

RF wins by count but the decision to use OLS is justified on four independent grounds:

1. Interpretability OLS produces a single equation: demand = slope × month + intercept. Any clinician or administrator can understand and audit it. Random Forest's 100 decision trees are a black box — inappropriate for a system that informs medical supply decisions.
2. Zero external dependencies OLS is implemented in 10 lines of pure NumPy which is already available in the Python standard scientific stack. Random Forest requires scikit-learn (~120MB). Minimising dependencies in a clinical system reduces maintenance burden and security surface.
3. Marginal accuracy improvement The average MAE gap is ~0.17 units per month. For a blood bank managing 5–12 units per group, this difference does not change any operational decision. A model that is 0.17 units more accurate does not stock a different number of units.
4. Dataset scale does not justify complexity Random Forest is designed for high-dimensional datasets with thousands of samples. With 23 monthly observations per blood group, RF is overkill and likely overfitting to noise. This comparison itself demonstrates that OLS matches or beats RF on 3 of 8 groups even on this small dataset where RF should theoretically have an advantage.
